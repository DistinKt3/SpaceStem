# Known Sky: Engineering Decisions and Assumptions

Product decisions live in `docs/PRD.md` Section 14 and are not repeated here. This log records the engineering decisions and the assumptions made where the PRD was silent or ambiguous. Each entry: what, why, and what would change it.

| ID | Date | Decision | Rationale | Revisit if |
|---|---|---|---|---|
| D-001 | 2026-10-10 | Use three.js `WebGPURenderer` only, with its built-in WebGL2 backend as the fallback. All custom shaders in TSL. No legacy `WebGLRenderer`, no raw GLSL. | One shader source for both backends; the PRD requires WebGPU primary plus WebGL2 fallback. | The WebGL2 backend of `WebGPURenderer` proves unfit in M0. |
| D-002 | 2026-10-10 | Pin `three@0.186.1` exactly (and `@types/three@0.186.0`). | WebGPU/TSL APIs change between releases; r186 already shows a render-time incompatibility with Chromium 141. | A needed fix lands upstream; upgrade deliberately with both-backend e2e. |
| D-003 | 2026-10-10 | Ship a WebGPU compatibility shim (strip identity `swizzle: 'rgba'` from texture views when the browser rejects it) and a boot-time probe frame that falls back to WebGL2 on any render error. | Observed: r186 throws on Chromium 141 at first render; three's `getFallback` only covers init failures. | three or browsers make it unnecessary. |
| D-004 | 2026-10-10 | Depth: partitioning is the baseline on both backends; reversed-Z with float depth is the default optimization where supported. No log depth. | PRD fallback ladder; reversed-Z gives ~1.2e-7 relative precision at all distances; log depth disables early-Z. | M0 tests show artifacts. |
| D-005 | 2026-10-10 | World axes are ICRF/J2000 equatorial, SI meters, float64 on the CPU. Frame tree: interstellar → star system → body-fixed. Camera-relative rendering every frame (camera at render origin). | Native frame of DE ephemerides and HYG; float64 per-system frames keep millimeter or better precision where the ship is. | — |
| D-006 | 2026-10-10 | M4 exoplanet system is **TRAPPIST-1**. Proxima Centauri appears as a known star in M3. | TRAPPIST-1 has measured radii and masses for seven transiting planets plus JWST constraints, so more of what we show can be Measured; Proxima b does not transit, so its radius and surface are unknown. | Owner prefers Proxima. |
| D-007 | 2026-10-10 | Star catalog for M3 is **HYG v4.1** (CC BY-SA 4.0), filtered to valid distances within 1,000 pc. Single tile; octree deferred. | Reachable now, includes names, covers "a few thousand light-years" for bright stars; ~100k stars needs no octree. | We add a Gaia subset (then octree tiles). |
| D-008 | 2026-10-10 | Planet and Moon ephemerides from JPL **DE421** (via the PyPI `skyfield-data` wheel), fitted offline to Chebyshev segments. Window 2020–2040, resized in M1 by measured size. Major moons via JPL Horizons when allowlisted; otherwise published analytic theories flagged as lower precision. | DE421 is reachable now and accurate far beyond what is visible. | Horizons access lets us use DE441 for everything. |
| D-009 | 2026-10-10 | "Major moons" for M1 = Moon, Phobos, Deimos, Io, Europa, Ganymede, Callisto, Titan, Enceladus, Triton, Charon. | The PRD does not define the set; these are the most recognizable and scientifically notable. | Owner wants more or fewer. |
| D-010 | 2026-10-10 | Offline pipeline in Python 3.13 with uv; runtime in TypeScript. | Astronomy tooling (jplephem, numpy, GeoTIFF readers) is in Python; the pipeline is not shipped. | — |
| D-011 | 2026-10-10 | TypeScript 6.0.x, not 7.x. | typescript-eslint supports TypeScript `<6.1`. | typescript-eslint supports 7. |
| D-012 | 2026-10-10 | HUD text and panels are DOM, styled as glass projection; spatial markers are in-scene. | Accessibility (text scaling, screen readers, translation) needs real text; the PRD prefers diegetic where possible, which the in-scene markers and styling preserve. | — |
| D-013 | 2026-10-10 | Cockpit is modeled procedurally in code; audio is synthesized in WebAudio. | No license risk, no external tools, small download. | Quality bar not met; then self-made models via scripted Blender (bpy). |
| D-014 | 2026-10-10 | Sim time is the player's real current UTC, clamped to the ephemeris window; shared links carry their own time. | "Real positions" means now; shared views must reproduce. | — |
| D-015 | 2026-10-10 | Committed data capped at 60 MB; larger tile packs go to versioned GitHub Release assets pulled by the deploy workflow. No Git LFS. | Repo-size rule; LFS free bandwidth would be consumed by CI. | — |
| D-016 | 2026-10-10 | Provenance is tracked per object and per displayed field (`Sourced<T>`). Detail synthesized below data resolution (e.g. terrain finer than the DEM) is labeled Generated. | One object mixes tiers (Earth imagery is Measured, sub-DEM terrain is Generated); honesty needs field-level labels. | — |
| D-017 | 2026-10-10 | Gameplay-relevant generation uses CPU integer hashing; GPU noise is visual-only. `Math.random` banned in `core/` and `world/` by lint. | Bit-exact determinism across machines; GPU float math is not bit-exact across vendors. | — |
| D-018 | 2026-10-10 | Browser tests capture frames in-page (render-target readback / `toDataURL`) and run Chromium with SwiftShader Vulkan flags. | Page screenshots of WebGPU canvases are black here; readback needs the flags. | Environment gains a GPU. |
