# Known Sky: Engineering Decisions and Assumptions

Product decisions live in `docs/PRD.md` Section 14 and are not repeated here. This log records the engineering decisions and the assumptions made where the PRD was silent or ambiguous. Each entry: what, why, and what would change it.

| ID | Date | Decision | Rationale | Revisit if |
|---|---|---|---|---|
| D-001 | 2026-10-10 | Use three.js `WebGPURenderer` only, with its built-in WebGL2 backend as the fallback. All custom shaders in TSL. No legacy `WebGLRenderer`, no raw GLSL. | One shader source for both backends; the PRD requires WebGPU primary plus WebGL2 fallback. | The WebGL2 backend of `WebGPURenderer` proves unfit in M0. |
| D-002 | 2026-10-10 | Pin `three@0.186.1` exactly (and `@types/three@0.186.0`). | WebGPU/TSL APIs change between releases; r186 already shows a render-time incompatibility with Chromium 141. | A needed fix lands upstream; upgrade deliberately with both-backend e2e. |
| D-003 | 2026-10-10 | Ship a WebGPU compatibility shim (strip identity `swizzle: 'rgba'` from texture views when the browser rejects it) and a boot-time probe frame that falls back to WebGL2 on any render error. | Observed: r186 throws on Chromium 141 at first render; three's `getFallback` only covers init failures. | three or browsers make it unnecessary. |
| D-004 | 2026-10-10 | Depth: partitioning is the baseline on both backends; reversed-Z with float depth is the default optimization where supported. No log depth. | PRD fallback ladder; reversed-Z gives ~1.2e-7 relative precision at all distances; log depth disables early-Z. | M0 tests show artifacts. |
| D-005 | 2026-10-10 | World axes are ICRF/J2000 equatorial, SI meters, float64 on the CPU. Frame tree: interstellar → star system → body-fixed. Camera-relative rendering every frame (camera at render origin). | Native frame of DE ephemerides and HYG; float64 per-system frames keep millimeter or better precision where the ship is. | — |
| D-006 | 2026-10-10 | M4 exoplanet system is **TRAPPIST-1**. Proxima Centauri appears as a known star in M3. | TRAPPIST-1 has measured radii and masses for seven transiting planets plus JWST constraints, so more of what we show can be Measured; Proxima b does not transit, so its radius and surface are unknown. | Owner prefers Proxima. |
| D-007 | 2026-10-10 | Star catalog for M3 is **HYG v4.1** (CC BY-SA 4.0), filtered to valid distances within 1,000 pc. Single tile; octree deferred. | Reachable now, includes names, covers "a few thousand light-years" for bright stars; ~100k stars needs no octree. | We add a Gaia subset (then octree tiles). |
| D-008 | 2026-10-10 | Planet and Moon ephemerides from JPL **DE421** (via the PyPI `skyfield-data` wheel), fitted offline to Chebyshev segments. Window 2020–2040, resized in M1 by measured size. Major moons via JPL Horizons when allowlisted; otherwise published analytic theories flagged as lower precision. | DE421 is reachable now and accurate far beyond what is visible. | Horizons access lets us use DE441 for everything. |
| D-009 | 2026-10-10 | "Major moons" for M1 = Moon, Phobos, Deimos, Io, Europa, Ganymede, Callisto, Titan, Enceladus, Triton, Charon. | The PRD does not define the set; these are the most recognizable and scientifically notable. | Owner wants more or fewer. |
| D-010 | 2026-10-10 | Offline pipeline in Python 3.13 with uv; runtime in TypeScript. | Astronomy tooling (jplephem, numpy, GeoTIFF readers) is in Python; the pipeline is not shipped. | — |
| D-011 | 2026-10-10 | TypeScript 6.0.x, not 7.x. | typescript-eslint supports TypeScript `<6.1`. | typescript-eslint supports 7. |
| D-012 | 2026-10-10 | HUD text and panels are DOM, styled as glass projection; spatial markers are in-scene. | Accessibility (text scaling, screen readers, translation) needs real text; the PRD prefers diegetic where possible, which the in-scene markers and styling preserve. | — |
| D-013 | 2026-10-10 | Cockpit is modeled procedurally in code; audio is synthesized in WebAudio. | No license risk, no external tools, small download. | Quality bar not met; then self-made models via scripted Blender (bpy). |
| D-014 | 2026-10-10 | Sim time is the player's real current UTC, clamped to the ephemeris window; shared links carry their own time. | "Real positions" means now; shared views must reproduce. | — |
| D-015 | 2026-10-10 | Committed data capped at 60 MB; larger tile packs go to versioned GitHub Release assets pulled by the deploy workflow. No Git LFS. | Repo-size rule; LFS free bandwidth would be consumed by CI. | — |
| D-016 | 2026-10-10 | Provenance is tracked per object and per displayed field (`Sourced<T>`). Detail synthesized below data resolution (e.g. terrain finer than the DEM) is labeled Generated. | One object mixes tiers (Earth imagery is Measured, sub-DEM terrain is Generated); honesty needs field-level labels. | — |
| D-017 | 2026-10-10 | Gameplay-relevant generation uses CPU integer hashing; GPU noise is visual-only. `Math.random` banned in `core/` and `world/` by lint. | Bit-exact determinism across machines; GPU float math is not bit-exact across vendors. | — |
| D-018 | 2026-10-10 | Browser tests capture frames in-page (render-target readback / `toDataURL`) and run Chromium with SwiftShader Vulkan flags. | Page screenshots of WebGPU canvases are black here; readback needs the flags. | Environment gains a GPU. |
| D-019 | 2026-10-10 | Reversed-Z is WebGPU-only. WebGL2 always uses depth partitioning. | Deviation from D-004 (which assumed reversed-Z on WebGL2 with `EXT_clip_control`): three r186's WebGL2 backend renders reversed depth correctly into render targets but outputs black through `RenderPipeline`. Partitioning passes the same precision tests. | three fixes reversed depth for WebGL2 post output. |
| D-020 | 2026-10-10 | Terrain LOD splits on screen-space geometric error (each chunk measures its own deviation), not on projected quad size. | Quad-size LOD produced 1.8 M triangles at ground level; geometric error gives ~0.37 M with no visible loss. | — |
| D-021 | 2026-10-10 | Data sources upgraded: the owner set network access to Full mid-session. Primary sources are used where reachable: JPL Horizons (all moons), NASA SVS CGI Moon Kit (LROC color, LOLA elevation), NASA Blue Marble NG, NOAA ETOPO 2022, Solar System Scope maps (CC BY 4.0), NASA Exoplanet Archive, ESA Gaia sky map. The GitHub/PyPI fallbacks (NASA-3D-Resources, vtk-data, DE421 via PyPI) remain documented in the manifest. | Highest quality was requested; the data is now reachable. | — |
| D-022 | 2026-10-10 | Committed data cap raised from 60 MB to ~150 MB; imagery ships as cube-face tile pyramids (WebP) in `public/data/`. | Deviation from D-015: release assets need `gh`, which this environment lacks, and the owner prioritized visual quality. Tile pyramids keep GPU memory and initial load small despite the larger repo. | Repo grows past ~300 MB; then move packs to a data branch or release. |
| D-023 | 2026-10-11 | Drive speeds: thrusters up to 3 km/s; impulse up to 0.05c; cruise from 2 km/s up to 3,000c. Impulse and cruise are capped by a governor proportional to distance from the nearest surface (0.6 and 0.9 × altitude per second), with automatic drop-out near surfaces. | Deviation from the PRD's proposed travel table (cruise ~0.1c to c). With cruise capped at c, Earth to Jupiter takes over 35 minutes and Neptune over 4 hours, which breaks the PoC's "Earth, Moon, onward" pacing. The governor makes arrival controllable at any speed. The HUD always shows speed as a multiple of c, and the Codex states that faster-than-light travel is fiction (PRD realism principle). | Playtests find cruise too fast to read the system, or the owner prefers the PRD numbers. |
| D-024 | 2026-10-11 | HUD spatial markers (target bracket, velocity vector, body labels, off-screen arrow) are DOM elements projected from the 3D camera each frame, not in-scene meshes. | Refines D-012. DOM markers stay crisp at any resolution, follow text scaling and colourblind palettes, cost no draw calls, and are readable by assistive technology. The glass styling keeps the diegetic look. | The cockpit glass needs markers to refract or sit behind cockpit geometry. |
| D-025 | 2026-10-11 | PoC views: cockpit (default), free camera (`?free=1`, also used for screenshots), system map and local-star map. External chase view and the galactic map are deferred. | PRD Section 10 lists chase and galactic map views, but Section 9a scope names only "map view" for M3. A chase view needs an exterior ship model; the galactic map needs data beyond 50 ly. | After M7, as stretch work. |
| D-026 | 2026-10-11 | Hyperspeed: 3 s spool, then a transit of 20 + 6·log10(1 + d/ly) seconds along a smootherstep profile, in an interstellar frame (SSB origin). Engaging is refused when landed or deeper than max(10,000 km, 2 radii) in a planet's gravity well. Arrival distance is max(1.6·sqrt(L/L☉) au, 120 stellar radii). | Fiction made explicit: about 24 s to Proxima Centauri, about 40 s to 1,000 ly. Arrival scales with luminosity so the destination star never fills the view or overexposes. The HUD shows the real distance and light-travel time. | Fuel and cooldown costs (M6) change pacing. |
| D-027 | 2026-10-11 | A visited star becomes a lit body whose radius, effective temperature and luminosity are Inferred from catalogue M_V and B−V (Ballesteros 2012 B−V→T_eff; bolometric correction from T_eff), and are labelled Inferred. | HYG gives magnitudes and colour, not radii; the inference is standard and keeps the visited star physically plausible. | Measured radii (interferometry, Gaia FLAME) are added for named stars. |
| D-028 | 2026-10-11 | System map: laid on the planets' mean orbital plane (normal of total orbital angular momentum), radial distance compressed as r^0.4, orbits drawn as osculating Kepler ellipses from current ephemeris state vectors. Star map: galactic plane horizontal, true positions, named catalogue stars within 50 ly. | Display-only choices that are stated on screen. The ephemeris window (D-008) covers far less than outer-planet periods, so sampled orbits were partial. Kepler ellipses are exact to drawing precision for the planets over decades. | — |
| D-029 | 2026-10-11 | Targetable destination stars are the 1,155 named HYG entries; the other ~108k stars are drawn in the sky but cannot be selected in M3. | Keeps target cycling and the map list usable; every target has a recognisable name. | M4 or later adds a scanner that can target any star in view. |
| D-030 | 2026-10-11 | Moon and dwarf-planet maps come from georeferenced USGS Astrogeology mosaics (Galileo, Voyager, Cassini, Viking, New Horizons), rolled to centre longitude 0 using each GeoTIFF's centre-longitude key. NASA 3D Resources maps are dropped except Deimos. Unimaged areas (value 0) are filled with the mean albedo and labelled Generated. | A license review found NASA 3D Resources' Titan map is a fictional concept, and its other maps carry no georeferencing. Pluto and Charon had been rotated by 180° and 0° by a fixed assumption; feature checks (Sputnik Planitia, Xanadu, Valhalla, Osiris) now pass. | Higher-resolution or colour mosaics become available. |
| D-031 | 2026-10-11 | Surface maps are scaled linearly so their area-weighted mean linear reflectance equals the body's measured geometric albedo (capped at 0.9); `albedoScale` is computed by `bodies.py` from the shipped texture. Exposure adapts to the geometric albedo directly, with at most 1.6× boost for dark bodies. | USGS and artist maps are display stretches with arbitrary scale. The rule reproduces the Moon's hand-tuned value (0.40) exactly. A power-law remap was tried and rejected because it washed out contrast. | Photometric (Hapke) parameters are adopted per body. |
| D-032 | 2026-10-11 | Titan is drawn as an optically thick haze deck: the disc takes Titan's measured visible albedo spectrum (Karkoschka 1994) and the Cassini 938 nm surface map shows through at 4%. A thin single-scattering layer adds the limb haze. | Titan's haze has a vertical optical depth of about 4–5 in the visible. The single-scattering model renders such a haze nearly black because Titan's brightness comes from multiple scattering. Showing the near-infrared surface as if seen in visible light would misrepresent it. | A multiple-scattering atmosphere model, or a near-infrared scanner view in the cockpit. |
| D-033 | 2026-10-11 | Audio: space is silent; the cabin hum and instrument tones are always on; drive sounds reach the pilot only as low-passed hull vibration; wind exists only in an atmosphere and scales with density × airspeed. A generative ambient score runs from a fixed seed (7, D Lydian), so every player hears the same piece. Every sound has a caption. | Implements owner decision Q9 (scored ambience plus honest silence). A fixed seed keeps the soundtrack recognisable and testable. | Players ask for variety; then use a seed per save. |
| D-034 | 2026-10-11 | Controls: every action is rebindable (two slots each for keyboard/mouse and gamepad). Escape and the gamepad Menu button are fixed to pause and settings. Clicking the view captures the mouse for steering; holding the right mouse button or Alt switches the mouse to head look. "Align nose to target" is a new action on N, since Y became "previous target". | PRD accessibility requirement (full remapping). Fixing pause keeps a guaranteed way out of every state. | — |
| D-035 | 2026-10-11 | Exoplanet systems use circular orbits phased by the measured transit midpoints, with each planet's measured inclination. The orientation of the orbits around the line of sight is a fixed Generated angle (transits cannot measure it). No light-travel-time correction is applied for the star's distance. Planets are tidally locked (Inferred from their short periods). Surfaces are Generated (palette chosen from the Inferred equilibrium temperature), and positions within a system are computed in its local frame. | Transit data constrain size, period, phase and inclination but not the node angle. The TRAPPIST-1 eccentricities are below 0.01 (Agol et al. 2021), so circles are accurate to display precision. The local frame avoids ~50 m of float64 loss at 12 pc. | Measured node or eccentricities matter for gameplay. |
| D-036 | 2026-10-11 | Codex provenance rules: Measured = a value quoted as the source published it; Inferred = model-dependent values, values the source marks as derived, and values the game computes from measurements (light-years, light times, ratios); Generated = anything the game makes up (exoplanet surfaces, terrain detail, the star brightness gain, the drive). No Measured fact may cite an unverified source (enforced by `tools/pipeline/codex_check.py` and `tests/unit/codex.test.ts`). | Makes the honesty rule mechanical and testable. | — |
| D-037 | 2026-10-11 | Codex unlocks come from play. Visiting a body (entering its sphere of influence) or arriving at a star or system discovers its entry. Concepts unlock the first time the game shows what they explain: targeting a star unlocks parallax and star catalogues; targeting an exoplanet unlocks transits and the exoplanet count; Proxima b unlocks radial velocity; arriving at TRAPPIST-1 unlocks tidal locking, the habitable zone and transit-timing variations; Earth's daylit sky unlocks why the sky is blue; opening the map unlocks ephemerides. "How do we know this?" opens for any target with an entry, even before the entry is discovered: provenance is never locked. Codex dialogs keep keyboard focus while open and return it to the game canvas on close. | PRD Codex goals: discovery is a reward, while the honesty layer is always available. Returning focus prevents a closed dialog from swallowing game keys, a bug the e2e test caught. | Playtests show players miss concepts; then add hints in the HUD. |
| D-038 | 2026-10-11 | Exoplanet orbit phases use a mean ephemeris (period and transit midpoint) fitted to the Agol et al. (2024) forecast of every TRAPPIST-1 transit from 2015 to 2027, labelled Inferred. The archive's catalogued period, an osculating value from an N-body fit, is still shown as Measured, under that name. Tidal locking is shown as "likely, not observed", citing Turbet et al. (2018) and Vinson et al. (2019); the generated ice placement assumes it. | The planets tug on each other (transit-timing variations), so propagating the osculating period drifts from the observed transits, while the mean period follows them (docs/EXO_TRAPPIST1.md §4). Vinson et al. show that d, e and f may not be fully synchronous, so locking cannot be stated as fact. | A published long-term ephemeris supersedes Agol et al. (2024). |
| D-039 | 2026-10-11 | Starlight has the star's colour. Planet surfaces, atmospheres, clouds, rings and the cockpit are lit with blackbody(T_eff) / blackbody(5772 K), scaled to unit luminance (`starlightTint`), so the Sun stays exactly white and brightness stays in the irradiance. Under TRAPPIST-1 (2,566 K) the tint is about (1.97, 0.80, 0.18) in linear RGB, so worlds look orange, as a camera white-balanced for sunlight would record them. No chromatic adaptation is applied. | Lighting every world as if by the Sun misrepresented other stars; the effect is large and real for M dwarfs. The blackbody colour uses the same approximation as the star discs (Helland's fit). Real M-dwarf spectra have molecular bands, so the hue is an approximation. | A spectral model per star, or a player-selectable 'eye-adapted' white balance. |
| D-040 | 2026-10-11 | TRAPPIST-1's distance is 1/parallax from Gaia DR3 (12.467 pc), not the NASA Exoplanet Archive's Gaia DR2 value (12.430 pc), and it is labelled Inferred. The star's T_eff, radius, mass and age are Inferred, each with a note on how the source derived it; luminosity, metallicity, spectral type and photometry stay Measured. The star body's HUD badge reads Inferred, as for catalogue stars. | The Codex already quoted the DR3 distance and these tiers, so the HUD, the data lab and the Codex disagreed. DR3 is newer and more precise. Agol et al. 2021 compute T_eff from L and R, derive R from the transit density and an empirically related mass (Mann et al. 2019), and the age comes from empirical indicators. Under D-036 these are Inferred. | The archive adopts DR3 for this star. |
| D-NEW-share | 2026-10-11 | Share links name the page only (origin and path, never the query), and the address bar never keeps a place the player has left: a link that has been applied (at boot or pasted while playing) is removed from it, and a copied link goes there only when the clipboard refuses it (until the next successful copy). Screenshot mode keeps sound captions on screen, ends when the map, settings or Codex opens, and does not lock the pointer on a click; captures are supersampled by rendering the scene target at up to 2× (at most a 2560×1440 target, off at the Low preset). | Query parameters are the sharer's device and debug choices (`?backend=webgl`, `?free=1`, the lab's `?reset=1` wipes settings) and must not reach the recipient. An unchanged fragment fires no `hashchange`, so a link left in the address bar could not be pasted again, and a reload would jump back. The image never contains DOM, so hiding captions only took cues from deaf players. Bloom, star sizes and terrain detail follow the canvas, not the scene target, so a supersampled capture matches the composed view. | Links need to carry a setting on purpose (then whitelist that parameter), or a renderer change makes the scene target's resolution visible in the image. |
